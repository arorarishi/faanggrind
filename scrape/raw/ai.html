Foundations

6 lessons · 14 h
  1. #1SkimBeginner 45 minHistory - how AI got to transformersAI did not jump straight to LLMs (large language models). Each generation of methods hit a wall, and the next idea was built to get past it: hand-written rules, then learning from data, then deep networks on GPUs, then attention, then transformers pretrained on huge amounts of text. This lesson walks that chain in order, so you can explain why a transformer looks the way it does and which problem each part solves.Open lesson
  2. #2StudyBeginner 3.5 hNeural networks and backpropA neural network is a stack of simple units. Each unit multiplies its inputs by weights, adds a bias and applies a non-linear function. Training means finding weights that make a loss number small. Backpropagation computes how much each weight contributed to the loss, and gradient descent moves each weight a small step in the direction that lowers it. This lesson covers both, plus the basics interviewers check: activations, losses, optimisers, regularisation, normalisation and metrics.Open lesson
  3. #3SkimBeginner 1 hRNNs, LSTMs, CNNsRNNs, LSTMs and CNNs are the three network designs that came before the transformer. An RNN reads a sequence one step at a time and carries a memory vector forward. An LSTM is an RNN with gates that protect that memory. A CNN slides small filters over an image. This lesson explains what each one solved, the limit each one hit, and which parts are still inside the models you use today.Open lesson
  4. #4StudyBeginner 3 hLLM fundamentals - tokens, embeddings, decodingAn LLM (large language model) is a neural network trained to do one thing: predict the next token. This lesson follows a piece of text through the whole machine. Text becomes tokens, tokens become vectors, a stack of transformer blocks mixes those vectors, and a decoding rule picks the next token from the output probabilities. You will work each stage with small numbers.Open lesson
  5. #5StudyIntermediate 2.5 hCoding simple attentionSelf-attention lets every token update its vector using the other tokens in the sequence. This lesson builds it in small steps: measure similarity with a dot product, turn the scores into weights with softmax, and take a weighted sum. Then it adds the three things a real layer needs: the scaling by the square root of d_k, the causal mask and multiple heads. Every step is worked with numbers you can check by hand.Open lesson
  6. #6StudyBeginner 3 hHugging Face end to endHugging Face is where open models live and the set of Python libraries used to run them. This lesson follows one path from start to finish: find a model on the Hub, read its card and licence, load the tokenizer and the weights, format a chat with the model's template, generate text, measure the output, and save or push your own version. Every step names the object you get back.Open lesson

Build with LLMs

4 lessons · 13.5 h
  1. #7StudyBeginner 2.5 hPrompting and context engineeringPrompt engineering is writing a good instruction. Context engineering is deciding everything that enters the context window: instructions, examples, retrieved data, tool definitions and history. This lesson covers both: the parts of a prompt, when to use few-shot examples or step-by-step reasoning, how to get valid JSON every time, how to keep a long conversation inside a token budget, and how to prove a prompt change helped.Open lesson
  2. #8StudyIntermediate 4 hVector DBs and RAGRAG (retrieval-augmented generation) fetches relevant text at query time and puts it in the prompt, so a model answers from your data without being retrained. A vector database makes the fetching fast: it stores an embedding for every chunk of text and finds the nearest ones to a query in milliseconds. This lesson covers both, from chunking to evaluation.Open lesson
  3. #9StudyIntermediate 3 hWhat is fine-tuning - LoRA, QLoRA, DoRAFine-tuning changes how a model behaves by updating its weights on your examples. Updating every weight of a large model is expensive, so the LoRA family freezes the base model and trains a small add-on called an adapter, usually under 1% of the parameters. This lesson explains LoRA from the formula up, then QLoRA, DoRA and rsLoRA, and how to choose between them.Open lesson
  4. #10StudyIntermediate 4 hFine-tuning a model for a real use caseThis lesson takes one real task, a model that sorts support tickets and drafts a reply, and walks the whole fine-tuning job from start to finish. You decide whether to fine-tune at all, build and clean the dataset, format it with the chat template, split it, train a QLoRA adapter, read the loss curves, compare with the base model, serve the adapter, and debug a run that made things worse.Open lesson

Serving

1 lessons · 3.5 h
  1. #11StudyIntermediate 3.5 hInference and serving - KV cache, batching, vLLMInference is running a trained model to produce output. Serving is doing that for many users at once, fast and cheaply. This lesson follows one request through an LLM server: the prefill and decode phases, the KV cache that makes decode fast, batching that keeps the GPU busy, quantization that shrinks the model, and the metrics and engines you use to run it in production.Open lesson

Agents

4 lessons · 15.5 h
  1. #12StudyIntermediate 4 hAgents from first principles - build a mini frameworkAn agent is an LLM running in a loop with tools: it chooses an action, sees the result, and repeats until the goal is met. A chatbot answers; an agent acts. This lesson builds a small agent framework piece by piece (message list, tools, registry, loop, error handling, limits), so you can explain what any agent framework is doing underneath.Open lesson
  2. #13StudyIntermediate 4 hAgent frameworks - LangChain, LangGraphAn agent framework gives you the loop, the state and the tool plumbing from the previous lesson as ready-made parts. This lesson names the eight frameworks interviewers expect you to recognise, then teaches you to read LangChain and LangGraph code line by line: tools, `create_agent`, state, reducers, nodes, conditional edges, checkpointers and interrupts.Open lesson
  3. #14StudyIntermediate 3.5 hTools, MCP and memoryA tool is a function your application offers to a model: a name, a description and a schema for the arguments. MCP (Model Context Protocol) is an open standard for packaging tools and data so any compatible AI application can use them. Memory is how an agent keeps facts beyond one context window. This lesson covers how to design all three, and what each one costs in tokens.Open lesson
  4. #15StudyAdvanced 4 hAgents in depth - patterns, reliability, securityThis lesson is about agents in production. It covers the seven architecture patterns and how each one fails, why long tasks fail more often than short ones, how to manage context over hours, how to make actions safe to retry with idempotency keys and checkpoints, how to evaluate an agent, and how to keep it from leaking data. It ends with a full design of a customer support agent.Open lesson

Ship

3 lessons · 9 h
  1. #16StudyIntermediate 3.5 hEvals, tracing and guardrailsAn eval is a repeatable test that tells you whether a change made an LLM system better or worse. A trace is the record of one request: every prompt, retrieval, tool call, token count, latency and cost. A guardrail is a check on what goes into the model or comes out of it. This lesson shows how to build all three, with the numbers and the wording interviewers expect.Open lesson
  2. #17StudyIntermediate 3 hLLM system designLLM system design is the interview round where you design a whole product around a model: a chat service, document Q&A, a support agent or a serving platform. Almost every answer uses the same five layers and the same seven steps. This lesson gives you the layers, the steps, the arithmetic for capacity, cost and latency, and the points each common question expects.Open lesson
  3. #18StudyIntermediate 2.5 hWhat is new in 2026 + revisionThis is the last stop before the interview. It lists the eleven 2026 trends an interviewer may probe, each with what it is, why it matters to someone who builds systems, and a line you can say. It then gives the 37-term revision sheet for the rapid-fire round, and a structure for answering "what have you been following lately?" in two minutes.Open lesson

Later

6 lessons · 15.5 h
  1. #19LaterAdvanced 1.5 hAttention variations - GQA, MLAStandard multi-head attention stores a key and a value for every head, every layer and every past token. That store, the KV cache, is the main memory cost of serving besides the weights. This lesson covers the variants that shrink it: multi-query attention, grouped-query attention (GQA) and multi-head latent attention (MLA). It also places FlashAttention and sliding-window attention, which solve different problems.Open lesson
  2. #20LaterAdvanced 1.5 hRL fine-tuningSupervised fine-tuning needs the right answer written out for every example. Reinforcement learning (RL) fine-tuning needs only a score: which of two answers a person preferred, or whether a program accepted the answer. This lesson explains policy, reward and policy gradient in plain words, then the three methods used on LLMs: RLHF with PPO, DPO and GRPO, with what each needs and how each fails.Open lesson
  3. #21LaterAdvanced 1.5 hComputer use and multimodal agentsA multimodal model reads images and audio as well as text, by turning each of them into tokens. A multimodal agent uses that ability to act: answer from documents with charts, hold a voice call, or operate a computer by looking at screenshots and clicking. This lesson explains how an image becomes tokens, how voice and computer-use agents are built, why they are slow and easy to break, and how to test and secure them.Open lesson
  4. #22LaterAdvanced 1.5 hAdvanced topicsThis lesson is a map of what to study after the core roadmap. It covers ten topics that sit one level below the basics: reasoning models, mixture of experts, distillation, constrained decoding, speculative decoding, long-running agents, harness engineering, open-weight models, the small tuned model plus RAG pattern, and GraphRAG. For each one you get what it is, why a system builder cares, and what to learn first.Open lesson
  5. #23LaterIntermediate 8 hProjects - RAG app, fine-tuned model, agent + evalsThree small projects turn the rest of this course into things you can talk about: a RAG app, a fine-tuned model, and an agent with an eval harness. This lesson gives each one a scope, milestones, numbers to measure with targets a student can reach, a README outline, and a way to present it in two minutes: problem, design, trade-offs, numbers.Open lesson
  6. #24LaterIntermediate 1.5 hLLMs on cloud - Bedrock, Azure OpenAI, Vertex AIAmazon Bedrock, Azure OpenAI and Google Vertex AI each give you one managed API to many models inside your own cloud account. The product names differ, but the ideas are the same: pay per token or reserve capacity, live inside quotas, choose where data is processed, lock access down with cloud identity and private networking, and add managed retrieval, agents, guardrails, tuning and evals. This lesson teaches the shared ideas and when to self-host instead.Open lesson
