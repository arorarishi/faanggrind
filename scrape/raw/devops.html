Foundations

6 lessons · 21.5 h
  1. #1StudyBeginner 2.5 hDevOps, SRE and platform engineering - how software reaches productionDevOps is a way of working that shortens the path from a code commit to a working change in production, and sends what production sees back to the people who wrote the code. This lesson explains what that means in practice, how the DevOps engineer, SRE and platform engineer roles differ, how the four DORA metrics measure delivery, what the 12-factor rules ask of an app, and how one change travels from a pull request to production and, if needed, back.Open lesson
  2. #2StudyBeginner 4 hLinux for operatorsEvery container, every Kubernetes node and almost every CI runner is a Linux machine. This lesson is the operator's view of Linux: where files live, who may touch them, how processes are born and killed, how systemd keeps a service running, where logs go, and how to read disk, memory, CPU and load numbers when something is wrong. It ends with the kernel features (cgroups and namespaces) that containers are made of.Open lesson
  3. #3StudyBeginner 3.5 hBash scripting and the terminal toolkitThe shell is the operator's first programming language and the glue of every CI job, Dockerfile and runbook. This lesson covers the model (three streams, exit codes, pipes), the text tools you chain together (grep, awk, sed, sort, uniq, cut, jq), how to write a bash script that does not break on a space or a missing variable, scheduling with cron and systemd timers, ssh, rsync and tmux, and the point where you should stop writing bash and switch to Python or Go.Open lesson
  4. #4StudyBeginner 3.5 hNetworking for DevOps - TCP/IP, DNS, HTTP, TLS, SSHNetworking is the part of DevOps you cannot avoid: every outage ends with a packet that did not arrive, a name that did not resolve, or a certificate nobody renewed. This lesson covers the layers you actually debug (link, IP, TCP, TLS, HTTP), CIDR arithmetic with a real VPC plan, DNS end to end, the HTTP status codes operators care about, where TLS terminates, SSH and bastions, load balancers, security groups, and the eight tools that find the fault.Open lesson
  5. #5StudyBeginner 3 hGit and trunk-based workflowsGit is the database every DevOps workflow is built on: application code, Terraform, Helm values, Kubernetes manifests and CI pipelines all live in it, and in GitOps a Git commit is the deploy. This lesson covers the Git model (snapshots, the DAG, branches as pointers), merge versus rebase versus squash, trunk-based development versus GitFlow, the pull request workflow, releases and hotfixes, bisect, hooks, monorepos, signed commits, and the ten Git situations that come up on call with the exact command for each.Open lesson
  6. #6StudyIntermediate 5 hPython and Go for automation and toolingA DevOps engineer needs two languages. Python is for scripts, checks, data and glue between APIs: fast to write, already installed everywhere. Go is for anything that ships as a single binary, does many things at once, or lives in the CNCF world, where Kubernetes, Helm, Argo CD, Prometheus and Terraform are written. This lesson shows the shape of a good Python ops script, the one page of Go a Python person needs, the worker-pool pattern with channels and context, and the mistakes that make Go tools leak.Open lesson

This lesson covers why the proxy is there, how an Nginx config is structured, the server block you will copy for years, load balancing across app processes, static files, rate limiting, TLS with Let's Encrypt and certbot, systemd versus PM2, and how to read Nginx logs and status codes.Open lesson
  2. #8StudyBeginner 3.5 hContainers and DockerA container is a normal Linux process that the kernel isolates with namespaces and limits with cgroups, started from an image made of read-only layers. This lesson covers images and the build cache, a production multi-stage Dockerfile, base image choices, tags versus digests, registries, the docker run flags that matter, networking and volumes, Compose for local stacks, deploying a monorepo to VMs with Docker and why that stops scaling, container security basics, troubleshooting, and how containerd and the OCI standards fit under Kubernetes.Open lesson
  3. #9StudyIntermediate 3.5 hCI/CD with GitHub Actions and GitLab CIA CI/CD pipeline is the set of automated jobs that run when code changes: lint, test, build an image, scan it, deploy it, and check that the deploy worked. This lesson teaches the shape of a good pipeline, then GitHub Actions in depth (triggers, matrix, caching, environments, OIDC to AWS, reusable workflows, security), GitLab CI as the equivalent, monorepo pipelines that build only what changed, runners on Kubernetes, and how to make a slow pipeline fast.Open lesson
  4. #10StudyIntermediate 3.5 hDeployment strategies and release engineeringA deployment strategy is the plan for moving user traffic from the running version of a service to a new one without breaking anything. This lesson compares recreate, rolling, blue-green, canary, A/B and shadow, then covers what cannot be rolled back (data), database migrations that stay backward compatible, graceful shutdown, feature flags, release trains and versioning, the deploy checklist, the Friday question, and how DORA measures whether your releases are good.Open lesson

Cloud and IaC

4 lessons · 15.5 h
  1. #11StudyIntermediate 5 hAWS core - IAM, VPC, EC2, S3, RDS, load balancers, autoscalingAWS is the cloud most Indian DevOps jobs ask for. This lesson covers the services every platform is built from and the one setting people get wrong in each: accounts and IAM (who may do what), VPC (where things live on the network), EC2 and Auto Scaling groups (the machines), load balancers (the front door), S3, RDS and Aurora (data), Route 53, CloudWatch, Systems Manager and Secrets Manager.Open lesson
  2. #12StudyIntermediate 5 hAWS managed platforms - EKS, ECS, Fargate, Lambda, SQS, ElastiCache, CloudFrontAWS offers five ways to run a workload: EC2 with an Auto Scaling group, ECS, EKS, Fargate, and Lambda. This lesson is about choosing between them and about EKS as an AWS product: node groups and Auto Mode, the VPC CNI, Pod Identity, access entries, add-ons and the load balancer controller. It also covers the services that sit beside the cluster: SQS and SNS, ElastiCache, CloudFront, and Secrets Manager through the External Secrets Operator.Open lesson
  3. #13StudyIntermediate 4 hTerraform - infrastructure as codeInfrastructure as code (IaC) means your VPCs, clusters, databases and IAM roles are written in files, reviewed in pull requests and created by a tool, not clicked together in a console. Terraform is the most common IaC tool. You write HCL, run plan to see the diff, run apply to make it real, and a state file remembers what Terraform owns. This lesson covers the language, state, modules, environments, CI and the moments where Terraform can destroy production.Open lesson
  4. #14SkimBeginner 1.5 hAnsible and configuration managementConfiguration management is the job of making a fleet of machines match a written description: these packages, this config file, this service running. Ansible does it over SSH with no agent, from YAML playbooks whose tasks are idempotent: run them twice and the second run changes nothing. This lesson covers where Ansible still fits once you have containers and Terraform, its model (inventory, plays, tasks, modules, handlers, roles, vault) and the mistakes that make it dangerous.Open lesson

Kubernetes

5 lessons · 21 h
  1. #15StudyIntermediate 4 hKubernetes architecture and core objectsKubernetes runs containers across a fleet of machines. You describe the state you want in YAML (three copies of this image, reachable on port 80) and a set of control loops makes the cluster match it and keeps it matched when things fail. This lesson covers the control plane, the worker node, the core objects (Pod, Deployment, Service, ConfigMap, Secret, Namespace) and the kubectl commands interviewers expect you to know cold.Open lesson
  2. #16StudyIntermediate 4.5 hKubernetes networking and storageLesson 15 said a Service is a stable address for pods. This lesson opens the box: how pods get IPs (the CNI plugin), how a Service's virtual IP is turned into real packets (EndpointSlices and kube-proxy or eBPF), how DNS names are built and why they cost extra queries, how HTTP gets in from outside (Ingress, Gateway API, the AWS Load Balancer Controller), how to restrict traffic (NetworkPolicy), and how disks work (PV, PVC, StorageClass, StatefulSets, EBS and EFS).Open lesson
  3. #17StudyAdvanced 5 hKubernetes in production - resources, autoscaling, RBAC, upgrades, EKSRunning Kubernetes in production is a set of decisions that nobody makes for you: how much CPU and memory each pod asks for, which pods die first when a node is full, how probes are timed, where pods may be scheduled, how pods and nodes scale, who may do what, what a pod may not do, and how to upgrade without an outage. This lesson covers each decision with the field names, the defaults and the numbers, and ends with a production checklist.Open lesson
  4. #18StudyIntermediate 3.5 hHelm - charts, templates, values and releasesHelm is the package manager for Kubernetes. A chart is a folder of Go templates plus a values.yaml with defaults; `helm install` merges your values into the templates, sends the resulting manifests to the API server and records the result as a release. This lesson covers the chart layout, the template language, values design, the release lifecycle with upgrades and rollbacks, dependencies, publishing to an OCI registry such as ECR, testing, and how Helm fits with Argo CD.Open lesson
  5. #19StudyIntermediate 4 hGitOps with Argo CD and progressive deliveryGitOps means the desired state of a cluster lives in Git, and an agent inside the cluster pulls that state and keeps the cluster matching it. Argo CD is the most used agent. This lesson covers the four GitOps principles, why pull beats push, the Argo CD objects (Application, AppProject, ApplicationSet), sync, drift and self-heal, repository layout and promotion, rollback by revert, secrets with External Secrets, Flux as the alternative, and progressive delivery with Argo Rollouts canaries.Open lesson

Operate

5 lessons · 20.5 h
  1. #20StudyIntermediate 4.5 hObservability - Prometheus, Grafana, OpenTelemetry, logs and alertingObservability is how you find out what a running system is doing from the outside: metrics (numbers over time), logs (events), and traces (one request's path across services). This lesson covers the Prometheus data model and the PromQL queries every on-call engineer writes, Alertmanager, Grafana dashboards, log shipping to Loki, distributed tracing with OpenTelemetry, the collector pipeline, and the arithmetic of what all of this costs.Open lesson
  2. #21StudyIntermediate 3.5 hSRE practice - SLOs, error budgets, incidents and postmortemsSite Reliability Engineering is software engineering applied to running services. Its tools are the SLI (what you measure), the SLO (the target), the error budget (how much failure you can afford), burn-rate alerts (how fast you are spending it), a practised incident response with named roles, and blameless postmortems that turn each outage into action items. This lesson gives the definitions, the arithmetic and the checklists interviewers ask for.Open lesson
  3. #22StudyIntermediate 4.5 hTroubleshooting playbook - Linux, Docker, Kubernetes, network, pipelinesTroubleshooting is a method, not a list of commands. Scope the damage, protect users before you understand the cause, follow the request path to the first broken contract, test one hypothesis with one command, change one thing at a time, and write down what you did. This lesson gives that method and then five dense playbooks (Linux host, containers, Kubernetes, networking, pipelines) where every row has a symptom, likely causes, a real first command, the evidence that confirms it, and the fix.Open lesson
  4. #23StudyIntermediate 4 hSecurity and DevSecOps - secrets, least privilege, supply chain, policy as codeDevSecOps means security is a property of the pipeline and the platform, not a review at the end. This lesson covers the controls a DevOps engineer owns: short-lived identity for humans, CI and pods; secrets that never touch Git; a supply chain where every image is scanned, pinned, signed and verified at admission; hardened pods and clusters enforced by policy as code; cloud hardening with private endpoints and audit logs; and the edge controls (TLS, WAF, rate limits, SSRF protection) that stop abuse before it reaches the application.Open lesson
  5. #24StudyIntermediate 4 hScaling and resilience - caching, queues, rate limiting, DDoS, DRScaling is making a system handle more load; resilience is making it keep working when parts fail. Both come from the same layered design: stateless replicas behind a load balancer, state pushed into databases, caches, object storage and queues, limits and timeouts at every hop, and a tested plan for losing a zone or a region. This lesson covers each layer with the numbers interviewers expect: cache hit ratios, queue semantics, rate limiter algorithms, retry budgets, connection pools, RPO and RTO.Open lesson
